# PhotoX Project Review — 2026-08-01

Full-repository review of the PhotoX monorepo (NestJS microservices + Vite web app): architecture, security, correctness, over-engineering, repo hygiene, test gaps. Conducted as a deepwork session: 5 parallel recon lanes → Oracle triage → 7 fixer lanes → Oracle diff review → final validation.

**Result: 25 findings fixed (in-tree), ~35 findings documented below as deferred, 0 false-positive fixes shipped. All gates passed (Oracle reviews ×3, typecheck, pact suite).**

## Fixed (25 items, landed in working tree)

### Security / ownership

| Finding | Fix |
|---|---|
| S1 · `registerFaces` accepted client-supplied `userId` (face-cluster poisoning) | Gateway now overrides `body.userId` with `req.user.id` (`assets-proxy.controller.ts`); media asserts asset ownership before insert (`faces.service.ts`); pact updated to exercise the override |
| S2 · cross-user person assignment | `assignPerson` verifies the person belongs to the user; `reassignFaces` scopes `personRepo.update` by `{id, userId}` and rejects foreign `toPersonId` |
| S3 · presigned-URL endpoint ignored `userId` | `getFileUrl` now scopes `{ id, userId }` + 404 for non-owners (`user-files.service.ts`); integration spec flipped to assert the 404 |
| S4 · permanent delete / orphan cleanup silently no-op'd | Internal delete renamed to `v1/internal/files/:fileId` (was shadowed by the user route via module import order — user deletes had also been served *without* ownership checks); both worker cleanup processors pointed at it; provider verifier now imports `InternalModule` (the bug was masked before) |

## Deferred (documented, not fixed — see rationale)

**Security/architecture:** compose hardcoded creds + published backend ports with `NODE_ENV=production` (I3 — trust-boundary decision; dev-only), web Dockerfile serves Vite dev server in prod (I4), refresh token in localStorage + `userId` in capability URLs (B32 — redesign: httpOnly cookie or memory store), no rate limiting on login/register (B17), `getOne` optional userId hardening (S5 — no live exploit path through the gateway).

**Known trade-off (B14):** `branchFor` trusts the FileRecord mime (client-supplied), and `application/octet-stream` now skips metadata extraction entirely where the old kind-based code would have run on it. Low risk (web uploads always carry a mime); revisit if arbitrary-mime uploads become common.

**Algorithmic:** face-cluster label→person mapping is per-run DBSCAN numbering, unstable across runs — needs centroid-distance matching + tests (B6+T1).

**Low-risk/edge:** 23505→409 on duplicate register (B12), HNSW index rebuild per boot (B13), Content-Disposition filename escaping (B15), duplicate cleanup jobIds (B16), incomplete 502 mapping (B17), `NOT IN` param limit (B19), `@IsUUID` on trash DTO (B20), TTL fail-fast (B21), health probe semantics (B22), `BullMqService.enqueue` still swallows errors — Redis blip = thumbnail/video jobs dropped with no user-visible signal (B8), unsanitized `getExtension` (D7), thumbnail video-frame fallback + status flap (D17), migration file dead weight + `synchronize: true` (D4), worker `dryRun` dead param (D3), duplicated thumbnail upload block (D6 — working hot path, churn not debt).

**Repo hygiene:** AGENTS.md drift (pact layout, `AUTH_CLOCK_TOLERANCE_SEC` location, `JwtPayload` role, `tsconfig.vitest.json`, `pnpm validate`), README (redis in compose-up, wrong filter name, missing services), `.dockerignore`, vitest `passWithNoTests` removal, `scripts/` workspace listing, MinIO `mc` healthcheck verification, base-builder `libheif`.

**Test gaps (all still open):** FaceClusterService (T1), cleanup processors (T2), ProxyService/BullMqService/AdminGuard/JwtStrategy units (T3), gateway upload/stream/derivatives + pact gaps (T4), worker thumbnail-video branch + Metadata/Face orchestration (T7), file-storage `list` (T8), web interceptor/useAssetGroups/share page (T6).
