# apps/core/src/albums/entities/

## Responsibility

TypeORM entities for the album domain: the album itself and the asset-membership join row. These are the only album tables; they are registered by `AlbumsModule` via `TypeOrmModule.forFeature`.

## Design

- `Album` (`albums` table): `id` uuid PK generated by TypeORM, indexed `userId` (`@Index()` on the column), `name` varchar(255), nullable `description` varchar(2000), `createdAt`/`updatedAt` timestamptz via `@CreateDateColumn`/`@UpdateDateColumn`.
- `AlbumAsset` (`album_assets` table): composite primary key `albumId` + `assetId` (both uuid `@PrimaryColumn`), indexed `assetId` (for "which albums contain this asset" and delete-cleanup lookups), `addedAt` timestamptz `@CreateDateColumn` used as the ordering key for album asset listings.
- Neither entity declares relations/FKs: `albumId`/`assetId` are plain uuid columns, so there is no DB-level cascade. Deleting an `Album` leaves its `album_assets` rows; permanent asset deletion explicitly removes `AlbumAsset` rows in the `AssetsService` transaction.
- `Album` has no uniqueness constraint on `(userId, name)` — duplicate names are allowed.
- No `deletedAt`/soft-delete; deletion is hard.

## Flow

- `AlbumsService.create` saves an `Album`; `list` uses `findAndCount` on the indexed `userId`; `update` patches by id; `delete` deletes by `{ id, userId }`.
- `addAssets` bulk-inserts `AlbumAsset` rows with `.orIgnore()` (ON CONFLICT DO NOTHING against the composite PK); `removeAsset` deletes by `{ albumId, assetId }`.
- `listAssets` joins `album_assets` → `assets` ordered by `addedAt DESC`, excluding `isTrashed`.
- `countAssets` joins `album_assets` → `assets` and counts non-trashed rows.
- `AssetsService.emptyTrash`/`delete` run `em.delete(AlbumAsset, { assetId: In(ids) })` in the same transaction as asset/face/share removal.

## Integration

- Owned exclusively by `AlbumsModule` / `AlbumsService`; no other module injects these repositories.
- `Asset` is imported from `@photox/data-access` (shared entity package) for validation queries, not re-declared here.
- Schema is created by TypeORM `synchronize: true` from `SharedDatabaseModule.forRoot()`; no migrations.
