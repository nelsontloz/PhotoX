# apps/web/src/components/Timeline/

## Responsibility

`TimelineGrid` — the virtualized, grouped justified gallery rendered by the timeline route (`/`). It joins the layout endpoint's reserved month buckets (structure + heights, via `hooks/useTimelineLayout`) with day-keyed `AssetGroup[]` fetched **per month** (via `hooks/useTimelineMonths`) and renders only the month buckets near the viewport, wrapped in a `DropZone` so the whole timeline accepts drag-and-drop uploads.

## Design

- Props: `layout` + `containerRef` (from `hooks/useTimelineLayout`), `groups`, `monthStatus`, `ensureMonth`, `refreshKey` (from `hooks/useTimelineMonths`), `onSelect`, `selectedIds`, `onToggleSelect`, `onLongPress`, `showCheckbox`. It does not fetch directly, measure, or compute heights — `useTimelineLayout` owns layout math/measurement and `pages/index.tsx` owns the loading gate + viewer/bulk-action state.
- **Virtualization (month granularity)**: the outer container is `position: relative` with `height: totalHeight`, so the scrollbar represents the full timeline from first paint. Each month bucket is absolutely positioned at `bucket.top` with `bucket.height` enforced and `display: flow-root` (margins can't collapse through). Inside a mounted bucket the day sections are in normal flow: each has an explicit `height` from layout data (`bucket.days[].height`, so a day whose assets haven't landed renders its sticky header over an exactly-reserved empty block), `mb-10` between days and `last:mb-0` so mounted content height ≡ reserved bucket height to the pixel (the +40 between buckets is applied in `top`).
- **Mount window**: buckets intersecting `[scrollTop - viewportH, scrollTop + viewportH * 2]` (visible range + one viewport of overscan above and below) render DOM; every other bucket renders nothing (space stays reserved by the container height + absolute tops). Scroll source is AppShell's `<main>` via `ScrollContainerContext`; `scroll` (rAF-throttled) + `resize` drive it. Outside an `AppShell` (no scroll container) all buckets mount — safe fallback.
- **Month fetch trigger**: an effect over the mounted bucket keys + `refreshKey` calls `ensureMonth(bucket.key)` for every bucket in the mount window (the existing `hasViewport` gate holds it until the real scroll container is measured; no container → fetch all, matching the mount-everything fallback). `refreshKey` in the deps is what makes an upload/trash bump re-fetch only what's on screen — `ensureMonth` itself dedupes, so scroll events are cheap map lookups.
- **Data join + skeletons**: buckets are day-keyed; each day section looks its `sortKey` up in a `Map` of `groups`. Found → real `GalleryItem`s. Not found and `monthStatus.get(day.sortKey.slice(0, 7)) === 'ready'` → the month is loaded but has nothing for that day (race with the layout fetch) → empty grid. Otherwise → **skeleton tiles**: plain non-interactive `<figure>`s built from the layout data's per-day items (`bucket.days[].items`, the exact `{ t, w, h }` list `buildBuckets` already grouped) carrying the same `--width`/`--height` vars GalleryItem starts with, with the shared `Skeleton` inside — identical packing inputs → identical rows → zero layout shift when the month lands. The grid container gets `aria-hidden` while it shows skeletons; "Select all" stays hidden for asset-less days. Fetched days label from the group, layout-only days from `groupDateLabelFromSortKey`.
- Tiles are laid out with the shared `justified-grid-gallery` utility (defined in `app.css`) plus its `fixed-row-gallery` modifier, inside a `max-w-6xl` container. The modifier is applied ONLY here — favorites/trash/albums/people keep plain `justified-grid-gallery` (variable ≥200px rows).
- **Fixed-row contract**: every photo row is exactly `--row-height` tall and CSS flex-wrap greedily packs rows from the items' aspect ratios alone, so month-section height is computable from data (see `lib/timelineLayout.ts`, which is the single source of truth). Exact formula, constants included:
  - `headerHeight` = 49px (sticky header: `py-2` 8+8, `text-2xl` line box 32, 1px transparent `border-b`) + `mb-4` 16px before the grid = **65px**
  - `rowHeight` = **200px** at viewport ≥40rem, **140px** below (media query on the modifier) — read from computed CSS by `useTimelineLayout`'s probe, never branched on in JS
  - gap **4px** between rows/columns, section `mb-10` = **40px**
  - `rows` = pure greedy pack of natural widths `wᵢ = rowHeight × widthᵢ/heightᵢ`: place on the current row while `rowHeight × Σaspect + 4 × (count − 1) ≤ W`, with `W` = the measured `max-w-6xl` container width.
  - `monthSectionHeight = 65 + rows × rowHeight + (rows − 1) × 4 + 40 (mb-10)`; bare box height without the `mb-10` margin is the same minus 40.
  - Last row stays ragged (not stretched): the `::after` filler absorbs free space, and under the modifier it carries `flex-basis: 0` + `margin-left: -4px` so it can never wrap onto its own line (a phantom line would add an extra gap and break the formula above).
  - Known ceiling (marked `ponytail:` in `app.css`): extreme-aspect images (panoramas) are center-cropped to the fixed row height instead of becoming short rows — the cost of predictable height.
- `onLongPress` is only wired on coarse-pointer devices by the page; touch selection vibrates via `navigator.vibrate(10)` there, not here.
- **Chronological scrollbar** (`TimelineScrollbar`, rendered inside the `DropZone` before the grid container): hides the native bar via a `.timeline-scroll` class toggled on AppShell's `<main>` (removed on unmount — other views keep the global scrollbar) and draws a fixed right-edge strip (`top-16`, the same header-height assumption as `DropZone`'s overlay, sitting over `<main>`'s right padding so it never covers content): a rail with one tick per month bucket mapped through `scrollHeight` (so ticks and the thumb's top edge line up exactly), January ticks longer + primary as year boundaries, a draggable thumb with hover grip lines, and a "Month Year" popup (`monthYearLabel`) visible while scrolling (1s grace), hovering, or scrubbing. Pointer scrub center-maps rail→`scrollTop` (`behavior: 'instant'` so the drag isn't lagged by `scroll-smooth`); geometry helpers are exported and unit-tested in `TimelineScrollbar.spec.ts`.
- `DropZone` filters dropped files to images/videos and shows a full-screen overlay; upload enqueueing is entirely in `lib/upload`.
- Sticky headers rely on `AppShell`'s scrollable `<main>` as the scroll container (exposed via `ScrollContainerContext`); this component manages no scrolling of its own.
- The group toggle flips only members whose selected state differs from the target, so it is a diff toggle rather than a blind select/deselect.
- Thumbnails re-mount on every virtualization window change, so `AssetThumb` keeps a session-long objectURL cache per thumb fileId (see `components/codemap.md`).

## Flow

Page renders `TimelineGrid layout={…} containerRef={…} groups={…} monthStatus={…} ensureMonth={…} refreshKey={…} onSelect={onClickAsset} …` → the mount-window effect fills months on demand → click either opens the viewer (`nav.open`) or toggles selection depending on `selectedIds.size` (page logic). Group headers call `onToggleSelect` once per member to flip the group. Dropped files → `enqueueFiles` → upload store → `useAppStore.bumpTimelineRefresh` → layout refetches + visible months re-fetch through `ensureMonth`.

## Integration

Single consumer: `apps/web/src/pages/index.tsx` (favorites/trash render their own grids manually). Depends on `../GalleryItem`, `../DropZone`, `../AppShell` (scroll container context), `../../lib/timelineLayout` (types), `../../lib/dateFormat` (`groupDateLabelFromSortKey`), and the `AssetGroup` type from `hooks/useAssetGroups`. Group labels/keys for fetched days come from `lib/dateFormat` (`groupDateLabel`, `groupDateSortKey`) applied in the hook, not here.
